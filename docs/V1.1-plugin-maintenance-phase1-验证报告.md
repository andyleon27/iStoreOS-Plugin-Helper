## 连通性检查地址

按顺序从现有 SSH 连接上的路由器执行：

1. HEAD `https://raw.githubusercontent.com/slobys/openclash-auto-installer/9a576f1e67512c1f6c6d932191ba3c6a7fd27661/LICENSE`
2. HEAD `https://api.github.com/repos/vernesong/OpenClash/releases/latest`
3. HEAD `https://github.com/vernesong/OpenClash/releases/latest`
4. GET OpenClash 同一 API 的轻量元数据，取得首个可信附件 URL。
5. HEAD `https://github.com/vernesong/OpenClash/releases/download/<真实标签>/<真实附件名>`，跟随 HTTPS 重定向但不下载附件正文。

任一步失败即显示“在线插件服务不可用 / 请确认代理已开启，并能够正常访问 GitHub。”，不继续读取包或其余版本。日志保留具体地址、HTTP 状态、退出码和耗时，不记录响应正文。没有伪造连通成功，也没有使用 Windows 端检测替代设备检测。

HEAD 限时 6 秒；元数据 GET 限时 10 秒、上限 1 MiB；SSH 命令限时 16 秒。只使用设备已有 curl，`-q` 忽略 curlrc；仅允许 HTTPS（包括重定向），不禁用证书验证、不改代理配置、不使用令牌、不写 cookie / 临时文件，不下载或执行脚本。缺少 curl、证书错误、限流、无可信附件等会报告不可用 / 待确认，详细原因在日志中。

## 本地状态与比较

- 读取 `/etc/os-release` 和必要时 `/etc/openwrt_release`。维护页独立检查 APK 数据库与 apk 可执行文件，或 opkg 可执行文件，不依赖 iStoreOS distfeeds 路径；不改变原有安装检测。
- APK：`apk info -v`；OPKG：`opkg list-installed`。复用现有纯解析函数，保留完整版本字符串。空 / 解析失败不会误报未安装。
- 主包依次为 `luci-app-openclash`、`luci-app-passwall`、`luci-app-passwall2`、`luci-app-nikki`、`smartdns`、`mosdns`、`daed`；另保留 `nikki`、`luci-app-smartdns`、`luci-app-mosdns`、`luci-app-daed` 的独立版本。
- 只有组件包时显示“仅检测到部分组件”，不会将 LuCI 版本当核心版本。没有运行任何插件二进制；包管理器未记录的手动安装无法据此识别。
- 普通插件仅比较分段数相同的明确点分数字版本，可剥离 `v`；双方都有 `-rN` 才比较修订。提交哈希、额外后缀、预发行、不同分段数均待确认。上游其它后缀如 `-2` 也保守显示待确认。
- SmartDNS / MosDNS 的核心版本与远端标签不强制比较。daed / OPKG 与通用上游版本不强制比较；daed / APK 仅在双方均为合法 `yyyy.MM.dd[-rN]` 时比较。独立 LuCI 标签仅展示。
- 验证例：`2026.08.21-r1` 对 `2026.07.31-r1` 显示“本地版本较新”，不会提示更新。

- Release x64：**0 warning / 0 error**。
- 全量回归：**659 passed / 0 failed**；原有 **611** 项完整保留，新增 **48** 项。含真实本地 `.run` 的两项只读元数据 / SHA256 检查。
- 窗口目检：主窗口仍为 760×500；维护页未连接、在线不可用、可控会话 Ready 三种状态均已检查。七行和 21 个禁用按钮完整显示，重试可清除旧状态，取消时等待当前读取退出；daed 反例显示本地版本较新。
- 已通过 GitHub API 只读核对上述八类真实元数据及其解析，其中 daed 五项列表约 211 KB。该开发机核对不代替路由器实际连通性验收。

- 新维护路径的命令白名单、URL 拒绝测试、接口能力检查及 UI 测试通过；没有安装 / 更新 / 卸载接口或执行回调。MIT 许可证与上游读取原文 SHA256 一致。
- `git diff --check` 通过；HEAD 未变，无 commit / push / tag / 发布或版本变更。当前工作区保留本次待验收修改，不能表述为 clean。

构建、全量测试、基线比对、开发机只读元数据核对及窗口图片保存在被 Git 忽略的 `artifacts/audit-v1.1-maintenance-phase1/`。设备侧 GitHub 与包状态的真实验收仍由用户在窗口中执行；开发测试使用可控会话，不冒充实机结果。
