## Candidate Selection

健康当前源保留 r3 快速路径：实际官方 Canary → 真实 apk/opkg update → 安装。没有候选列表读取或测速，不为性能主动切换健康当前源。

需要备用源时，延迟读取 QuickStart 动态列表，按规范化源 URL 和完整 feed 集合去重，排除已经尝试的当前源。HTTPS 优先，同协议原始顺序保持。没有镜像数据库或固定镜像排名。

Fast Canary 仅用于备用源筛选，使用同一 ProbeOne / Parse：curl Range 0-0、max-filesize 1、connect-timeout 2 秒、max-time 3 秒；SSH 命令上限 5 秒。正常 Probe 仍为 connect-timeout 5 秒 / max-time 15 秒，未替换。

最多快速检查 5 个唯一 HTTPS candidate。快速 HTTP 阶段预算 9000 ms，采用 Stopwatch 实际耗时，并在开始下一次前预留完整 3000 ms；Full Verification、QuickStart 读取、真实 update 另行计时。

- 成功 Canary <=1200 ms：Good Enough，立即 Full Verification；FULL 则暂停搜索并使用，不扫描后续镜像。
- 较慢成功 Canary 保留。没有 Good Enough 时，按成功 Canary 的实际延迟从低到高完整验证，失败后检查第二快。
- Fast 失败 / 超时不作为永久 DOWN。已成功的 Canary 写入正常缓存供 Full 复用；失败仅保留在 Fast 缓存，正常超时 fallback 仍可尝试。
- 可达但不 FULL 的候选不切换；完整验证任一失败即停止该候选。所有成功候选不可用后，按原正常串行策略检查未完成正常验证的候选，HTTP 也在该阶段兜底。
- 同一镜像 Fast Canary 最多一次，正常完整验证最多一次。Fast timeout 后正常 fallback 可以再次请求 Canary，属于不同超时模式；不重复已经成功的索引。
- 已 FULL 候选真实 update 或安装器出现明确官方仓库错误时，继续惰性序列中未尝试的源；不重新开始扫描。非源 / 辅助源等失败策略保持。

实际切换仍检查：原文备份、实际 identity、完整 distfeeds 一致、真实 update。Full 的相同 URL 集合在切换后不重复 HTTP。

## Persistent SFTP Monitor

每个 Monitor scope 持有一个 PersistentInstallerMonitor，首个 Poll 创建受信任 SFTP client 并 Connect，此后复用，结束 / 异常 / 状态未知离开 scope 时 Dispose。正常成功 Monitor 的 createTransfer / Connect 计数为 1；上传仍使用原独立短连接，上传代码段与 r3 一致。

生产 `SshInstallationWorkflowSession.Installer` 每次访问会创建新的包装对象，因此 WorkflowInstaller 在监测 scope 内捕获一次实际 Installer，并将整个 scope 与所有 Poll 绑定到同一对象。旧 session 的 Reconcile 也捕获同一监测对象；快照等非监测操作继续使用当前 SSH session。

IsConnected=false，或读取出现明确 SshConnectionException / SshOperationTimeoutException / SocketException / EndOfStreamException 时，Dispose 旧连接，经原 createTransfer 工厂建立新连接，继续同一 RemoteTempSession 与调用方原始 stdout/stderr offset。每次读取最多重连重试一次，重复失败交回既有状态未知 / SSH 恢复策略，不循环认证、不再次 StartInstaller。

认证 / Host Key 连接拒绝直接失败；权限、无效 exit、普通文件系统 IO 错误不自动当作断线重试。重连写入诊断，Monitor 收尾记录连接数。HostKeyTrustStore、SshService 与原受信任工厂未改。

ReadExit / ReadLog 的 raw byte[]、独立 byte offset、65536 chunk、0–255 严格 exit、缺失 exit=RUNNING、EOF 处理与 exit 后尾日志排空保持。HUP、launch.once、atomic exit.code、远程 session / 清理命令不改。

InstallationWorkflow 最终写入一行 Timing Summary，成功、失败和已知阶段均可记录：

`Preflight / SourceSelect; PackageUpdate; UploadIntegrity; SnapshotBefore; InstallerRuntime; SnapshotAfterVerify; RestoreCleanup; CandidateSelection; CandidateFullVerify; Total`

单位 ms，Stopwatch 单调计时，阶段重复发生时累加。CandidateSelection / CandidateFullVerify 是源选择细分项，不能再与其父阶段相加；Total 为本轮实际持续时间。未进入的阶段为 0。恢复旧 pending installer 的检查属于本次准备流程，同时记录其监测 / 验证细分时间。计时不决定成功、失败、重试或安装状态，也不改变主 UI。
