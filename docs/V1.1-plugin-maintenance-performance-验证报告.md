## 并发和渐进展示

1. 在后台读取系统版本、SDK、架构、包管理器及七个插件的本地包状态，不等待 GitHub。读取方式和包解析函数保持。
2. 立即报告独立的本地状态快照，UI 显示当前版本，远端列显示“正在检查…”。
3. 每次扫描创建一个 `SemaphoreSlim(4, 4)` 请求池。Raw HEAD、OpenClash GET、其余插件版本 GET 均受同一上限约束，HTTP 读取在工作线程执行。每个读取有独立 SshCommand / SSH channel，复用现有已认证 SSH 连接，不新建连接或共享命令对象。
4. Raw 和 API 连通检测与其余只读版本查询重叠执行，避免再增加串行门禁。Raw 和 OpenClash 有效正式元数据均成功，显示在线可用；关键请求失败显示不可用，本地状态保留。
5. OpenClash API GET 只执行一次，同时判断 API 能力及读取该行版本，不要求附件存在。OpenClash 行不等待慢 Raw；每个其它插件完成后立即报告自己的快照，不等待全表。
6. 单个 API 超时 / HTTP 错误会被转为该远端版本未知，不清空本地包状态、不导致其它插件失败。OPKG daed 通用版与独立 LuCI 查询也加入同一请求池；LuCI 失败不影响已获得的核心版本。
7. UI 通过在 WinForms 线程创建的 `Progress<PluginMaintenanceUpdate>` 接收更新。状态快照复制包字典，后台不会继续修改已经提交给 UI 的行。
8. 扫描期间禁用“重新检测”，另保留 `busy` 防重入检查。每轮使用扫描编号，丢弃旧扫描延迟回调。刷新立即将远端列重置为检查中，再读取本地状态。
9. 关闭窗口时取消队列，并等待全部在途读取完成后再释放现有 SSH 忙碌状态；请求池也在全部任务退出后释放。没有遗留任务与下一次检测 / 原安装流程争用连接。

没有生产代码中的 `Thread.Sleep`、`.Result`、`.Wait()` 或同步 UI 等待。保留既有 SSH / curl 同步读取接口，用有界后台任务承载；没有引入框架或修改全局线程池。

核对了当前依赖的 [SSH.NET 2026.0.0 SshClient 源码](https://github.com/sshnet/SSH.NET/blob/2026.0.0/src/Renci.SshNet/SshClient.cs)与 [Session 源码](https://github.com/sshnet/SSH.NET/blob/2026.0.0/src/Renci.SshNet/Session.cs)，采用独立命令 / 通道复用连接。未修改、升级或复制依赖源码。

## 请求数量和超时

前置能力检查从 **5 次减至 2 次**：

- HEAD `https://raw.githubusercontent.com/slobys/openclash-auto-installer/9a576f1e67512c1f6c6d932191ba3c6a7fd27661/LICENSE`
- GET `https://api.github.com/repos/vernesong/OpenClash/releases/latest`，复用正式版本元数据

不再执行 GitHub API HEAD、GitHub Release 页面 HEAD、OpenClash 附件 HEAD。其它六个插件继续使用第一阶段相同的正式 Release API，版本解析和结果不变。没有因性能优化新增远端来源或改变版本查询范围。

正常全扫描请求总数：APK 为 **8**（1 Raw HEAD + 7 metadata GET）；OPKG 为 **9**（另有独立 daed LuCI GET）。所有 HTTP 请求合计最多同时 4 个。重试不会同时启动另一套扫描。

超时和安全限制不变：curl connect 3 秒，HEAD 总限时 6 秒、GET 总限时 10 秒，SSH 命令限时 16 秒；元数据上限 1 MiB，仅 HTTPS、不跳过证书验证、不下载附件、不写脚本或临时文件。

日志包含开始本地检测、本地完成时间、Raw 检测、API 检测与复用说明、开始并行查询、每个插件完成、整体结果及总耗时。正常末行例如“插件维护检测完成，总耗时：5.8 秒”；失败 / 取消末行标注相应状态。每个实际 HTTP 请求仅记录一次 URL / HTTP / exit / 耗时。

## 预期性能（推算，尚非本轮实机计时）

用户旧版实机约 **29 秒**。采用用户给出的 Raw 2.0 秒、OpenClash 2.3 秒、其余 API 2.3～2.6 秒，按四槽调度估算远端部分约 **4.9 秒（APK）/ 6.8 秒（OPKG）**。OPKG 保留原有 daed 独立 LuCI 查询，其延迟暂按同类 API 2.3 秒估计。

加上本地 SSH 读取和调度开销，常见整体预计约 **5～8 秒**。本地状态在 SSH 本地读取完成后立即提交 UI；健康局域网下期望打开后约 0～1 秒先显示，仍需实机确认，不设置硬性承诺。若多个 API 接近 4 秒、发生限流或达到原有超时，总耗时会更长，不承诺固定 4～7 秒。

此次没有用开发机联网测速或模拟时钟冒充路由器实测。实际改善以用户新窗口日志的本地完成与总耗时为准。调度计算保存在 `projected-timing.json`。
