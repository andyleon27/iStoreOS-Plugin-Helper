## 实现

SSH 仍负责控制和后台派发。`SshPluginInstallSession.PollInstaller` 改为 `SftpInstallerPoller.Poll`，通过原 `createTransfer` 创建 trusted SFTP client；每次 Poll **一次创建、一次 Connect**，依次检查 / 读取 exit.code、stdout.log、stderr.log，结束后 Dispose client 与本次 ConnectionInfo。没有为三文件分别建连接，没有创建不校验 Host Key 的旁路 client。

`SshService`、HostKeyTrustStore 及原 CreateTrustedTransfer 未修改。SFTP client 仍验证与受信任 SSH 指纹一致；重连沿用既有设备身份验证和新连接工厂。小接口 IInstallerFileSession 只用于隔离文件流边界和测试，生产适配器仅包装原 createTransfer 的返回值。

新增 Poll 行为：

- 缺少 exit.code → ExitCode=null。存在则最多读取 65 bytes，小文本 Trim 后必须为 ASCII 数字且 0–255，否则抛出“安装器结束状态不可读”。空、负数、溢出、非数字、尾随 NUL 等均拒绝。原子 exit.tmp → exit.code 不变。
- stdout / stderr 各按独立 long offset Seek，循环处理短读，每路最多 65536 bytes。缺文件为空；刚通过 Exists 后消失也安全返回空，权限 / 连接异常不伪装成空日志。
- offset==长度为空；offset>长度为空并返回诊断，不回退造成重复日志；负 offset 在创建连接前拒绝。
- 输出保持 byte[]，不经 string / Base64 编解码。保留 UTF-8 跨块、CR/LF、进度控制字符与任意原始字节。
- 原监测 / 重连监测已有 65536 分块排空判断，保持原判定，不改安装状态机；只补充输出 offset 异常诊断。收到结束标记后仍排空日志，最后才进入原验证 / 恢复 / 清理流程。

Runner 保留 fork 前 shell 内建 `trap '' HUP`、cd 私有目录、标准流重定向、独占 mkdir launch.once、作者脚本单次派发、原退出码与原子结束标记。CheckRunner 只检查内建 HUP trap，不检查外部 sh / base64 / dd / nohup / stat。删除旧 SSH ReadExit / ReadLog 命令生成器。

| Runner control | 基础 sh、mkdir、mv；trap / test / printf / 重定向为 shell 能力 |

## 仅开发用 Runner Smoke

测试程序集提供 `--runner-smoke` 交互入口，复用产品 SshService / Host Key 工厂、SshPluginInstallSession、Launch / SFTP Poll / Exit / Cleanup。只上传固定合成脚本，输出 RUNNER_STDOUT_OK、RUNNER_STDERR_OK 和受控大日志，再退出 0，不读用户插件、不执行包管理器或软件源修改。未知派发状态不再次执行或提前清理。

入口与合成脚本仅位于测试程序集，不进入用户 UI 或便携 ZIP。自动 Smoke 用 fake session，真实 x86 Smoke 待 N1 安装成功后由用户运行；方法见 [开发 Smoke 说明](runner-smoke-r2.md)。
