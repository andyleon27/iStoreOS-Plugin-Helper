## 2. 卸载最终映射

用户本轮附件明确要求统一卸载并删除对应配置。本轮不读取或修改第三方 Shell 内容，继续直接执行指定脚本：

| 插件 | 卸载参数 |
| --- | --- |
| OpenClash | uninstall.sh openclash --delete-config |
| PassWall | uninstall.sh passwall --delete-config |
| PassWall2 | uninstall.sh passwall2 --delete-config |
| Nikki | uninstall.sh nikki --delete-config |
| SmartDNS | uninstall.sh smartdns --delete-config |
| MosDNS | uninstall.sh mosdns --delete-config |
| daed | uninstall.sh daed --delete-config |

确认框无“保留配置/同时删除配置”选项，显示将卸载插件并删除对应配置、建议提前自行备份，取消仍为默认键盘操作；只有点击“确认卸载”才继续。不添加备份功能，不自行删除额外文件，不承诺恢复出厂状态。删除范围以第三方脚本为准。

安装 / 更新仍分别为 install.sh、passwall.sh、passwall2.sh、nikki.sh、smartdns.sh、mosdns.sh、daed.sh，均无新增选项，不调用 menu.sh。固定 upstream commit、下载、SHA256、SFTP、执行流、退出码、日志、单任务锁和清理实现保持。

## 3. .run 成功后保留已选镜像

修改集中在既有 InstallationWorkflowService.FinalizeContext：主 package 独立验证成功、安装器已结束时，记录 SourceRetained 并保留现有选择。源名称来自实际 Software.CurrentSource，不硬编码镜像名。日志明确“插件安装完成。当前使用的软件源：… 已保留当前软件源设置。”

没有重新测速、没有第二次选源或切换，没有删除原依赖安装 / package update Gate，也没有改动 PluginInstallationService、runner、SFTP 监测或 .run 执行命令。没有创建新的备份、历史或恢复机制。

失败、取消准备、校验失败等场景仍走原有恢复分支；恢复失败仍保留原备份和未完成标记。安装器尚未结束仍不得恢复或提前清理。成功保留的任务不会被误认为“原源未恢复”，不会阻止后续操作。旧 runner 重连确认成功时沿用原选择的信息，不重新执行 .run。临时安装目录和已有源备份仍按原机制清理。

## 5. 页面与手动切换行为

维护页顶部“软件源”为次级按钮。正常打开维护页不会创建软件源窗口、扫描镜像或增加前置请求。用户点击后才打开 SoftwareSourceForm，先异步读取当前配置及系统；用户再点“检测可用镜像”才运行多镜像检测，显示可用性、平均响应时间、HTTP 404 等失败与当前使用标记。

列表行保存对应 SoftwareRepairPlan，用户选择检测 FULL 的目标并点击“切换到所选软件源”，直接传递这个目标的真实 identity，选择清华不会因中科大较快而自动换成中科大。失败或外来目标不能切换；所有候选名称、版本和耗时来自当前结果。

独立切换只调用一次原 POST 接口，并读取一次当前源 metadata 以更新标签，不再次测速，不执行 opkg update / apk update，不备份、回滚或恢复，不升级系统，不重试插件操作，也不重扫七个插件。接口响应不明确时不重复 POST；当前源未确认目标时显示未完成，不静默宣称成功或回滚。未额外写入用户第三方源、代理或插件配置。

读源、检测和切换均在后台 Task 执行，Progress 与 await 返回 WinForms UI 线程。窗口期间禁用检测/切换防止重叠；检测关闭会取消后续探测，提交切换后关闭会等待本次命令完成，不用取消来伪装写入未发生。SshService 的当前连接身份与既有 softwareBusy / pending installer 门禁同时保护操作。

## 6. 安装/更新失败辅助入口

仅第三方安装或更新返回 ScriptFailed（非零退出码）时显示条件提示：“如果日志中提示软件源下载失败、软件包索引异常或依赖缺失，可以尝试检测并切换软件源。”

原退出码、失败状态、实时 stdout/stderr 和结束后插件刷新保持。顶部软件源按钮与失败辅助按钮调用同一个窗口创建回调。打开或切换软件源后不会自动再执行失败操作、升级系统或重扫插件。卸载失败只保留原错误；连接中断仍为未知状态，不被判断成源错误。没有引入错误规则库，不把 daed 的内核能力问题断言成源问题。

七插件列表位置和第三方说明保留。失败提示采用日志下方紧凑两列排布，检查过正常和 125% 缩放，避免提示把日志区挤没。主窗口仍为 760×500。
