# 插件维护终端字体与 PTY 尺寸同步修复

日期：2026-10-28（Asia/Taipei）。本轮只处理终端显示与尺寸同步，使用本地 WinForms、GDI 和离线 Shell/SSH 替身验证；没有连接 N1，也没有读取真实设备 banner。

## 已复现的原因

### 1. 控件 Font 是 Consolas，不代表每个字符实际使用 Consolas

原实现设置 `new Font("Consolas", 11F)`，但 RichEdit 默认启用自动字体绑定和双字体规则。在本机将同样的 10 个块字符插入实际 TerminalView 后，`SelectionFont` 显示为 **Segoe UI Symbol**，字宽由 ASCII 的 8 像素变成 14 像素。

GDI `GetGlyphIndicesW` 证实 Consolas 本身包含 `▀▄█`，三项均不是缺字标记，且与 M/i/W/空格的字宽相同。因此本机问题不是缺少这些字形，而是 RichEdit 自动绑定把它们换成了不同宽度的符号字体。`▀▄█` 组成的登录 Logo 会由此拉伸和错位。

### 2. 列数使用了不同于实际绘制的测量结果

原 Columns 使用不带控件 DC 的 `TextRenderer.MeasureText("M", Font, ..., NoPadding)`。本机该值为 16 像素，实际 RichEdit 字符位置和控件 DC 的 GDI 测量均为 8 像素，导致列数约少报一半。原 Rows 使用 Font.Height，且未考虑自动换字体带来的行高变化。

此外，ClientSize 不等于原生文字排版矩形；文字内边距和出现的滚动条也需要扣除。[EM_GETRECT 文档](https://learn.microsoft.com/en-us/windows/win32/controls/em-getrect)描述了这一区别。

### 3. 初始尺寸与 resize 存在时序缺口

窗口只在开始菜单准备时捕获一次 columns/rows。下载和上传期间用户仍可 resize，但 PTY 最后使用的是先前捕获值。

原 TerminalView 只在 OnResize 时转发尺寸，Bind 没有同步。菜单控制器在 Start 之前会拒绝 Resize，因此绑定附近发生的 resize 也可能丢失；没有后续 resize 就不会再次发送。滚动条变化未必产生相应托管 Resize 事件。

## 修改内容

### 字体和网格

- 在 Consolas、Lucida Console、Courier New 中选择实际存在、包含 `▀▄█`、且这些字符与 ASCII 具有相同 advance 的字体；拒绝悄然替换为比例字体。
- 清除 RichEdit 的 IMF_AUTOFONT、IMF_AUTOFONTSIZEADJUST、IMF_DUALFONT，保留其他语言选项。原生句柄重建时，在 RichTextBox 恢复已有内容之前配置，防止旧日志再次发生字体替换。[语言选项文档](https://learn.microsoft.com/en-us/windows/win32/controls/em-getlangoptions)、[设置选项文档](https://learn.microsoft.com/en-us/windows/win32/controls/em-setlangoptions)。
- ASCII/块字符使用验证过的终端字体。补充平面字符（本轮覆盖 emoji）使用局部 Segoe UI Emoji / Symbol 字体，不让它改变相邻块字符字体；中文仍可通过系统字形链接显示。原始文字、复制粘贴和 UTF-8 数据不改变。
- 使用控件 DC 实测字格，结合 EM_GETRECT 与 ClientRectangle 的交集计算完整可见行列，计入原生文字边距、滚动条。移除虚报至少 20 列/6 行的规则；PTY 尺寸仍限制在既有的 1～1000 边界内。
- 段落采用与字格一致的固定行距，避免后备字体撑高行高；更新字号时同步调整。使用原生 [PARAFORMAT2 精确行距规则](https://learn.microsoft.com/en-us/windows/win32/api/richedit/ns-richedit-paraformat2)，未改变 TerminalScreen 的 VT 解析。

### PTY 尺寸

- 初次显示前完成布局，获取当前可见网格。
- 增加可选的尺寸获取回调，在菜单准备完成、PTY 创建之前重新读取 UI 网格；解决准备期间 resize 后初始参数陈旧的问题。
- Bind、OnResize、字号/DPI/原生句柄变化和既有 UI 定时器均检查尺寸。只有 Resize 成功入队后才记为已同步；Start 前被拒绝的尺寸会重试，成功后对相同尺寸去重。
- 继续使用既有的异步 Resize → ChangeWindowSize 路径；不在 UI 线程进行网络 I/O。滚动条变化也能在既有定时器上被检测到。
- 最小化不发送 1×1 等不可见网格，保留最后的可见尺寸，恢复后重新同步。TerminalScreen.ViewRows 同步更新。
