审计日期：2026-10-31（Asia/Taipei）。本报告比较**实际引用 DLL 的可协商集合**与上游默认配置，不把“库能解析”“默认提议”“设备实际提供”混为一谈。没有调整算法顺序或启用额外算法。

## 明确发现与本轮决定

1. **没有发现所审计 OpenWrt / Dropbear 默认启用、而 SSH.NET 缺失的必需现代服务器算法。** 当前常见交集包括 Curve25519、group14/SHA-256、AES-CTR + HMAC-SHA-256、ChaCha20、Ed25519、RSA/SHA-256；D26/W26 新增的 SNTRUP/ML-KEM 也已在固定 SSH.NET 中实现。
2. **ModernAlgorithmMissing（OpenSSH 扩展差异，非 OpenWrt 默认根因）：** UMAC、SK/WebAuthn 相关 host-key 名称，以及 OpenSSH 10.6 的 `ssh-mldsa44-ed25519` / `ssh-mldsa44-ed25519-cert` 不在 SSH.NET 2026.0.0 的提议集合。OpenSSH 存在成熟端实现；固定 SSH.NET 无对应内置实现。若目标服务器被配置为只允许这些类型，会缺少交集；这不是目前案例 A 的已确认配置。建议等待/评估上游 SSH.NET 成熟支持，本轮不自行实现或导入密码算法。
3. **Legacy 缺项：** ssh-dss、截短 SHA-1/MD5 MAC、RC4、Blowfish、CAST、3des-ctr、即时 zlib 等没有可靠的现代默认需求证据；不建议为一句“协议对不上”添加它们。
4. **既有 legacy 支持仍保留：** SHA-1 KEX、CBC/3DES、ssh-rsa 等原库默认能力没有在本轮增加或删除。它们仍构成在遗留服务器上协商到旧协议的既有风险；用户要求暂不改算法集合/优先级，因此本轮如实记录，不静默切换策略。
5. **未发现本项目人为限制现代算法。** 所有正式客户端现由统一工厂创建，不操作五个算法字典；五个实际字典及其顺序与原 NuGet DLL 完全相同。SFTP、SCP、SSH #2 继续受原设备指纹信任规则约束。
6. **案例 A 根因仍未知。** 缺少用户固件版本、ServerVersion、协商字段、DisconnectReason 和完整异常，不能在这份矩阵基础上反推真实设备一定缺少算法。需要该用户用新诊断版本复测。

审计源文件与固定 ref/commit 元数据保存在 `artifacts/v1.1.1-ssh-protocol-20261031/algorithm-sources/`；不读取或更改用户的路由器配置。本轮没有改动算法优先级，没有新增弱算法。
