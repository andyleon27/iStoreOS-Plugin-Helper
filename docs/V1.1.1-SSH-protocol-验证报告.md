## 两个案例的独立结论

**案例 A：尚不能确定根因。** “SSH 协议错误 / 两个协议对不上”不足以判定算法没有交集，更不能确定是 KEX、Cipher、MAC 或 Host Key。未知 SSH.NET 异常现在明确归为 GenericSshProtocolError，不猜测为算法不匹配。需要原用户用新诊断版本复测，带回 ServerVersion、已确定的协商信息、DisconnectReason 和异常链。

**案例 B：与 #1829 的版本、平台和症状高度一致。** 可以确定当前基线库存在该接收 MAC 状态缺陷，并已用原始 DLL 的确定性负对照证明；但现场缺少具体 mscorlib 版本和协商 MAC，尚不能排除其他真实完整性错误。对现场最终归因仍须原用户复测闭环，不能因本机能连接就宣布原设备已修复。

确认修复的库缺陷：某些 .NET Framework HMAC 实现在 `TransformFinalBlock` 后没有完整恢复可重用内部状态，SSH.NET 2026.0.0 在接收多个 packet 时重用同一对象，导致下一包的 SHA-2 MAC 错误或 SHA-1 CryptographicException。它与服务器 Host Key 是 Ed25519 并不矛盾；Host Key 签名算法和传输 MAC 是不同层次。[官方 #1829](https://github.com/sshnet/SSH.NET/issues/1829)

## 算法审计结论

[完整矩阵](V1.1.1-SSH-algorithm-matrix.md)逐项列出 KEX、Cipher、MAC、Host Key、Compression 的支持、OpenSSH 默认、Dropbear/OpenWrt 默认、安全性质、项目需求和当前启用状态。

- 未发现所审计 OpenWrt 24.10 / Dropbear 2024.86 与当前 main / Dropbear 2026.94 默认必需现代服务器算法在 SSH.NET 中缺失。ML-KEM、SNTRUP、Curve25519、SHA-2 DH、ChaCha20、AES-GCM/CTR、SHA-2 MAC、Ed25519、ECDSA 和 RSA/SHA-2 均已支持。
- OpenSSH 10.6 的 UMAC、SK/WebAuthn 和 ML-DSA/Ed25519 混合 Host Key 等属于另外的 ModernAlgorithmMissing 扩展差异；不能把它们推断为案例 A 的根因。若服务器被配置为仅允许这类算法，可能没有交集。已有成熟 OpenSSH 端实现，当前固定 SSH.NET 无相应内置实现；本轮不自行实现。
- 缺失的 DSS、MD5/截短 MAC、RC4、Blowfish、CAST、3des-ctr、即时 zlib 等没有现代默认必需证据，不新增。
- 未发现本项目人为删除或禁用现代算法。五个实际算法字典及其顺序与原 NuGet DLL 完全相同。原库已启用的 SHA-1 KEX、CBC/3DES、ssh-rsa 等 legacy 能力如实保留，属于既有风险；本轮遵照要求不调整优先级或集合。

## 分类、诊断和连接策略

错误分类优先采用类型、DisconnectReason 和 inner/aggregate exception，仅对固定库的精确 `MAC error` 和 `No matching … algorithm (server offers …)` 模板补充匹配。区分 AuthenticationFailure、HostKeyChanged、Timeout、NetworkUnreachable、MacError、KeyExchangeFailed、AlgorithmNegotiationFailed、ConnectionAborted、EnvironmentDetectionFailed、GenericSshProtocolError，保留 Cancelled/Other。Generic 与旧 SshProtocolError 保持相同枚举值，旧用户提示保留；新增具体错误有对应提示。

成功时与失败前的日志按明确 allowlist 读取：

| ConnectionInfo 字段 | 日志字段 |
| --- | --- |
| ServerVersion | Server |
| CurrentKeyExchangeAlgorithm | KEX |
| CurrentHostKeyAlgorithm | HostKey |
| CurrentClientEncryption | ClientCipher |
| CurrentServerEncryption | ServerCipher |
| CurrentClientHmacAlgorithm | ClientMAC |
| CurrentServerHmacAlgorithm | ServerMAC |
| CurrentClientCompressionAlgorithm | ClientCompression |
| CurrentServerCompressionAlgorithm | ServerCompression |

额外记录 patched 库 informational version、mscorlib 文件版本及 DisconnectReason。AEAD 显示集成认证、无独立 MAC；未协商字段为 unknown，不从默认列表推测。日志单行有长度边界，并沿用密码及 URL 编码密码脱敏；不序列化认证对象，不输出用户名、密码、私钥、session key、shared secret、cookie 或原始 Host Key material。公开 Host Key 指纹沿用既有日志。

连接工厂统一默认算法、密码认证、8 秒连接超时、30 秒 keepalive；命令、上传、监测各自原有操作超时仍保留。SSH #2 原先额外覆盖为 10 秒，现在也遵守统一 8 秒握手策略。工厂默认拒绝 Host Key，必须附加正式的首次信任或已确认指纹规则；没有任何自动接受变化的路径。

## 剩余兼容性风险

案例 A 缺少现场日志，根因未定；案例 B 需要受影响的 mscorlib/真实协商组合复测。仅允许库不支持的 OpenSSH 扩展算法、或定制弱/古老算法的设备仍可能没有交集。原库 legacy 默认能力仍存在，本轮没有新增也没有改变顺序。Windows 7 和 R2S 的硬件边界未因离线通过而自动扩大。

MAC 缺陷已按官方语义修复；未知异常、真正数据损坏、网络中断、Host Key 变化仍按安全规则停止，不通过重试、接受新指纹或切换弱算法来掩盖错误。
