## 2. UTF-8 边界修正

先按 V2 原实现移植并运行测试，结果为 75 passed / 1 failed。失败场景：

1. 第一块只有 UTF-8 前导字节 E4，decoder 暂存该前缀。
2. 下一块是完整的 8,192 个 ASCII 字节。
3. decoder 需要输出一个替代字符加上全部 ASCII，即 8,193 个 UTF-16 字符；原实现只提供 8,192 长度的 char buffer，会使会话以错误结束。

V1 改为按 Encoding.UTF8.GetMaxCharCount(bytes.Length) 分配字符缓冲区，保留同一个流式 Decoder。回归验证输出为一个 U+FFFD 加上完整 8,192 个 A，没有文本丢失或异常断开。

证据：
- [初次专项日志](C:/Development/iStoreOS-Plugin-Helper/artifacts/terminal-phase1/terminal-release-initial.log)
- [修正后的专项日志](C:/Development/iStoreOS-Plugin-Helper/artifacts/terminal-phase1/terminal-release.log)
- [移植初始源文件哈希](C:/Development/iStoreOS-Plugin-Helper/artifacts/terminal-phase1/port-baseline.json)

除这一修正外，三个生产核心文件的实现与 V2 对应源码一致，仅有命名空间和 using 适配。V2 源文件未修改。

## 6. 风险与后续接入条件

- 本阶段未连接真实 ShellStream/PTY 或路由器；SSH 适配、菜单 launcher、任务退出证据和远端文件清理仍需后续阶段验证。

- 历史上限为 4,000 行，单行长度没有字符硬上限；复制当前视图也不等于导出完整原始日志。超长连续输出的内存策略属于后续独立设计。
- UI 线程应异步等待 session 完成并排空显示队列，避免同步阻塞消息循环。StopAsync 关闭 transport，不提供“远端安装已安全取消”的保证；后续菜单接入仍需独立确认远端进程结束，才能清理和允许下一任务。
