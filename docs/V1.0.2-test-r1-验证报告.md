## 最小修复

- `PluginInstallCommands.Launch` 不再依赖外部 nohup / setsid。父 shell 在后台 fork **之前**执行内建 `trap '' HUP`，子 shell 继承忽略 SIGHUP；后台命令 stdin、stdout、stderr 全部与 SSH channel 分离，安装输出仍分别写 stdout.log / stderr.log。
- 原样保留随机专属 session、symlink 校验、原子 `mkdir launch.once`、只执行一次作者脚本、立即保存原退出码、临时 exit.tmp 经 mv 发布 exit.code。没有新增自动第二次派发、强杀或提前清理。
- 新统一 RunnerCheck 逐项检查 sh / base64 / dd；缺失项写 stderr 并 exit 127，HUP trap 不支持时也具名失败。不会安装任何路由器依赖，也不会因缺工具跳过日志或断线防护。
- `SshPluginInstallSession` 的能力检查异常与 APK / OPKG 快照异常分别带操作上下文；`PluginInstallationService` 在能力检查前后记录独立阶段，避免把空错误误读成换源失败。

该 HUP 策略依据 [POSIX trap](https://pubs.opengroup.org/onlinepubs/009604399/utilities/trap.html) 与 [shell 信号继承规则](https://pubs.opengroup.org/onlinepubs/000095399/utilities/xcu_chap02.html)：空 action 忽略信号，忽略状态传给被调用程序。没有扩展到 TERM / KILL，也不承诺不受设备断电或其他终止信号影响。

安装主编排、镜像选择、POST 实际状态判断、update、原源恢复、SFTP、SHA256、Makeself、Package Diff、独立验证与重试策略保持。`PluginInstallationService` 只增加阶段日志；安装派发顺序没有改变。UI 设计不变，仅显示版本加 r1，避免与旧测试窗口混淆。
