# V1.1.1 无 SFTP 设备完整安装监测验证

日期：2026-10-31（Asia/Taipei）。本轮在前一阶段 SCP 上传 fallback 的未提交工作区上继续实现，无提交、Tag、发布或重新打包；没有修改 V1.1.0 Release。

## 当前能力

已补齐“确认 SFTP subsystem 不可用 → SCP 上传 → SSH 增量监测 → 独立验证 → 清理”的完整链。**可进入无 SFTP 的 R2S 完整实机安装验收阶段；尚未进行 R2S 实测，不能视为已经通过硬件验收。**

正常 SFTP 设备继续使用原 SFTP 上传及 `PersistentInstallerMonitor`。不会因普通网络、认证、Host Key、超时或文件权限错误改用 SSH 文件监测。必须先有本轮上传过程中取得的明确 subsystem 初始化失败证据，才可启用 SSH 读取。

## 实现与安全语义

- SFTP 不可用证据保存在本轮 `RemoteTempSession` 对象上，而不是一次性安装适配器上。它随同一任务跨适配器、SSH 重连和未完成任务恢复保留；新任务默认为没有证据。SFTP 上传成功会清除该标记。设备身份检查和安装互斥仍由原工作流控制。
- SSH 监测仅在现有受信任首页 SSH 连接上创建只读 exec channel，不创建额外 SSH 登录，不修改服务器配置，不安装工具。重连后通过正式会话的活动连接工厂获取新的 SSH 客户端，不继续读取旧连接。
- 命令只使用 shell 内建能力、`wc -c` 和 `dd`。不需要 base64、Python、额外 SFTP 软件或非通用的 `dd iflag` 参数。BusyBox 的标准参数依据已核对：[wc](https://github.com/mirror/busybox/blob/1_36_stable/coreutils/wc.c)、[dd](https://github.com/mirror/busybox/blob/1_36_stable/coreutils/dd.c)。本机 Shell 测试使用 Git Bash，真实 R2S BusyBox / Dropbear 的执行表现仍须硬件验收。
- 只读取本轮受限目录中的 `stdout.log`、`stderr.log`、`exit.code`，及其存在性 / 长度信息；拒绝父目录和文件符号链接、目录型文件及不可读异常。
- 返回协议含版本、任务 ID、文件长度、分块长度和结束帧。三路原始字节按长度传送，各 stdout/stderr 分块最多 65536 字节，exit 文件最多 64 字节，响应总长度有上限。
- 使用 SSH.NET `ExecuteAsync` 后直接读取 `OutputStream`，避免字符串转换改变 NUL、任意字节或跨块 UTF-8。实现依据：[SSH.NET 2026.0.0 SshCommand](https://github.com/sshnet/SSH.NET/blob/2026.0.0/src/Renci.SshNet/SshCommand.cs)。监测释放时仅释放命令 channel，不关闭首页 SSH。
- 首先取得 exit.code 的存在性 / 长度，再取得日志长度，防止先读日志长度、后发现结束状态而遗漏最后输出。文件尚未生成表示仍运行；空日志合法；空、损坏或超范围 exit 文件不作为结束证明。
- stdout/stderr 独立按调用方字节 offset 增量读取。文件变短不回退 offset、不重复输出。大日志在退出码出现后仍排空全部分块，再允许结果验证和清理。原 UTF-8 解码及整行脱敏逻辑继续复用。
- 只接受受限 exit 文件中的 0–255 数字状态；SSH 命令本身也必须提供 exit-status=0。协议错误、错误任务 ID、额外数据、截断、命令失败和永久断线均不能被日志中的“成功”关键字覆盖。
- 断线由原工作流在同一设备身份约束下重连，以原 offset 重读；不重传或重启已经派发的安装器。永久断线 / 无有效结束证明继续保持未知、保留现场；恢复后可读取同一任务并完成验证和清理。
- 保留取消边界：安装前取消则不执行安装器并清理；安装派发后忽略准备阶段取消，继续监测，不终止或重复执行远端安装器。
- 上传后的大小 / SHA256、包快照、主 package 独立验证、软件源收尾和 session 清理仍按原安全流程执行。

监测开始时日志明确显示 `安装监测：SFTP` 或 `安装监测：SSH fallback（设备无 SFTP subsystem）`，恢复旧任务时同样记录。

## R2S 实机验收建议

1. 保持 R2S 原有无 SFTP subsystem 配置；确认 SSH、package update 正常，且固件自带 `scp`、`sha256sum`、`dd`、`wc` 可用。无需安装 openssh-sftp-server。
2. 使用与 `24.10-snapshot / aarch64_generic / OPKG` 匹配的可信 `.run` 和 IPK 分别完整安装；OPKG 设备仍应拒绝本地 APK，APK 实机安装须另在 APK 设备验证。
3. 确认日志包含 SCP 切换、上传 SHA256 通过及 `安装监测：SSH fallback（设备无 SFTP subsystem）`；stdout/stderr 持续增长且最终日志完整。
4. 确认受信任 exit.code、安装后快照、主 package 独立验证和 session 清理全部有结果；单凭“安装成功”文本不算通过。
5. 验证短暂断线恢复仍监测同一安装器、不重复执行；无法恢复时保留现场，后续恢复原任务可收尾。
6. 分别检查上传中取消和安装派发后取消的边界；首页 SSH 不被监测 scope 关闭。
7. 在正常 SFTP 的 N1 复测，日志应显示 `安装监测：SFTP`，原上传和监测路径保持不变。

剩余实测风险主要为具体固件的 SCP 命令可用性、BusyBox/Dropbear 行为和长日志读取速度。读命令设 15 秒超时，单通道每轮最多 64KiB；真实断线、损坏状态文件等仍会按安全语义保留未知，不能承诺所有异常情况下都得到成功状态。因缺少 SFTP 本身造成的监测缺口已补齐。
