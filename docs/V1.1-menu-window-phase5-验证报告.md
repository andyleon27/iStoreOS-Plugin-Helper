## 2. 首页入口的状态与复核

`SshService.GetMaintenanceMenuAvailability(expected)` 仅读取已有连接与任务状态，不发 SSH 命令、不发 HTTP 请求、不创建 SFTP，不重复认证。返回 Ready、NotConnected、Busy、PendingInstallation、IdentityUnconfirmed 或 Closed 及说明。

入口要求：

- 首页未关闭，且没有打开的维护窗口或首页连接、检测、安装任务。
- 当前 SSH 仍然连接，认证工厂可用。
- 当前设备 IsConnected 且 Host Key 与同一主机/端口已信任的指纹相符。
- 既有 softwareBusy/connecting 互斥未占用，且没有待确认的旧安装任务。

初始未连接时入口禁用；获得可信连接后启用。首页连接计时器每秒刷新，忙状态变化也随原 RefreshInstallButton 立即刷新。即使安装流程保留了可自动重连的凭据，已断开的 SSH 也不会启用维护入口。

防止显示快照过期的复核顺序：

1. 入口 LinkClicked 再读取当前 UI、连接、身份和任务状态，不仅检查 Enabled。
2. 设置 maintenanceWindowOpen，避免重入或程序化重复点击打开第二个窗口。
3. 新窗口 OnShown 再读取可用状态；不满足时只显示原因，不调用 runner。
4. SshService.RunMaintenanceMenuAsync 在原 sync 锁内再次检查并原子取得忙状态；可用快照不能绕过真正运行门槛。

首页仍可见，作为模态窗口的 owner 在维护窗口期间由 WinForms 禁止操作；返回时恢复首页。不会隐藏后重建首页或替换它的 SSH 对象。

## 3. 终端窗口行为

窗口默认客户区为 960×660，最小外框 800×540，支持调整尺寸。上方显示原项目来源、MIT/版权说明、独立的 SSH 连接状态、准备/运行状态及错误/清理详情；主体为原 TerminalView；底部为键盘提示和“返回首页”。

首次显示时自动调用阶段 4 的菜单运行入口，使用终端实际行列数。隐藏后再次显示不会启动第二次任务。准备进度用简短状态展示，菜单终端保留原脚本输出，不混入准备日志或不可见运行协议标记。

绑定回调通过同步 Invoke 切到窗口 UI 线程，确保在读取和启动短命令前完成 TerminalView.Bind。若窗口已请求关闭、已释放或令牌已取消，延迟绑定会被拒绝，不能再发送启动命令。

SSH 连接状态和菜单状态分别显示：菜单正常/异常退出后 SSH 仍可能连接；网络断开显示 SSH 已断开，最终结果依据阶段 3/4 的证据分类，不将断线当正常退出。已知退出但清理失败时显示原退出结论和清理警告。

网络运行任务结束后，在 UI 线程分批绘制全部待处理输出，再展示最终结果或关闭窗口。正常退出不会自动关闭窗口，便于查看和复制输出。键盘、回车、Ctrl+C、复制粘贴、滚动及 Resize 沿用既有 TerminalView/菜单控制器链路。

## 4. 返回与安全关闭

“返回首页”和标题栏关闭使用同一路径：

1. 设置本窗口关闭标记，禁用返回按钮，显示正在关闭状态。
2. 取消本窗口的链接令牌，取消准备或请求关闭菜单通道；CloseAsync 幂等。
3. 窗口保持 UI 消息循环和输出绘制，等待阶段 4 读写任务结束、远端状态复核和允许的清理完成。
4. 排空绘制队列，才完成窗口关闭与 ShowDialog 返回。
5. 将运行结果、错误及清理警告写回首页日志，包括无法确认时保留的远端任务路径；重新计算维护入口可用状态。

窗口只处理菜单控制器和自己的令牌，不调用首页 SshService.Dispose。关闭整个首页时，传入的 owner token 则取消子窗口任务。直接 Dispose 窗口也会取消本次任务，并释放 TerminalView，以解除可能等待其有界输出队列的生产者。

没有强制杀远端进程、无条件删除运行目录、重复启动菜单或自动重连重发操作。未完成的未知状态仍沿用之前阶段的保留策略。

## 6. 风险

1. 本轮没有真实路由器 SSH/SFTP/PTY 或上游菜单执行，设备端兼容性和网络故障时序仍需真实环境联调。
2. 安全返回需要等待已有 I/O 取消和有界状态复核，网络异常时可能有等待。关闭终端通道不能保证远端插件动作停止；未知结果会保留目录，并在首页日志记录路径。
3. 按钮可用检测确认当前会话和任务门槛，不预先保证 GitHub/代理可达；下载失败会在新窗口显示，不自动重试。
4. 菜单与首页共享底层 SSH 连接，关闭菜单不会主动断开首页；底层网络故障仍会影响两者。退出码只表示菜单进程的返回结果。
5. 已检查当前 Windows 环境的默认/最小尺寸布局；其他 DPI、字体和真实原菜单的长输出仍需用户环境验证。
6. 存在上述一次未稳定复现的既有终端 UI 测试等待超时，最终专项和全量结果通过，不能据此视为已定位其根因。

原未提交工作和前三阶段/阶段 4 的已有改动均已保留；无 stash/reset/clean、提交、推送或真实设备操作。
