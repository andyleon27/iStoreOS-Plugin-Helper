## 2. 固定 SHA 下载与校验入口

### 自动解析 main，一次解析后固定本任务

~~~csharp
await service.PrepareMenuAsync(session, progress, token);
~~~

顺序为：
1. 核对 session 已连接并取得同一准备任务互斥。
2. 从既有 CommitApi 解析一次 main 的完整 commit SHA。
3. 按该 SHA 请求 menu.sh 与 LICENSE；后续不会再次读取 main。
4. 验证 HTTP、响应体大小、严格 UTF-8、预期 /bin/sh shebang、NUL、原始 MIT 许可与版权信息。
5. 原字节写入本地 menu.sh 和 LICENSE，生成带来源/SHA 的 NOTICE.txt。
6. 对三个文件分别计算本地 SHA256，使用原 SFTP 接口上传到本次远端目录。
7. 对三个文件读取远端 SHA256，严格绑定完整文件路径并逐一比对。
8. 记录结果，再清理远端、本地任务目录后返回。

默认成功任务为一次 commit 请求、两次固定 SHA 文件下载、三次上传和三次远端 hash 校验。

### 调用方显式指定完整 SHA

~~~csharp
await service.PrepareMenuAtCommitAsync(session, fullCommitSha, progress, token);
~~~

SHA 参数在任何网络/文件操作前验证，允许输入十六进制大写并统一生成小写 URL。此入口直接下载固定 SHA 的 menu.sh 与 LICENSE，不查询 main。

DescribeMenu 的 SourceRef 标记为 commit；原七插件 Describe 的 SourceRef 和参数语义不变。menu.sh 追加在原 Scripts 数组末尾，没有改变 MaintenancePluginKind 的索引。

没有增加可变 ref、任意 URL、任意文件名或“下载失败后转 main”回退能力。helper-launcher.sh、PID/退出文件不属于上游下载白名单。

### 准备结果的生命周期

返回 MaintenancePreparationStatus.PreparedExecutionDisabled 仅表示准备校验预览通过，且本次临时文件已清理。菜单结果始终：
- Plan=null；
- ExecutionAttempted=false；
- ExitCode=null；
- 菜单 Workspace.Plan(...) 明确抛出 NotSupportedException。

清理失败时即使 IntegrityVerified=true，也返回 Failed/Cleanup 和明确路径/警告，不能当作完整准备成功。取消不复用调用方已取消的 token 进行清理，仍使用原来独立且有界的清理 token。

后续启动菜单需要在同一次已验证、尚未清理的目录生命周期内接入执行/交接；不能拿本阶段结果的 RemoteDirectory 直接运行。

## 3. 菜单任务文件结构

根目录及 GUID 隔离规则沿用原实现：

~~~text
/tmp/istoreos-plugin-helper/
  maintenance-<32位任务GUID>/
    .owner
    menu.sh
    LICENSE
    NOTICE.txt
    helper-launcher.sh   （显式启用时的本地 helper payload，本阶段不生成）
    menu.pid             （预留运行状态）
    menu.start           （预留运行状态）
    menu.exit            （预留运行状态）
    menu.exit.tmp        （预留原子退出写入）
~~~

| API / 集合 | 语义 |
|---|---|
| CreateMenu(id) | 本阶段使用；Files 只有 menu.sh、LICENSE、NOTICE.txt。 |
| CreateMenu(id, true) | 显式将 helper-launcher.sh 纳入上传/hash payload；仅建立结构，本阶段不生成 launcher 内容。 |
| Files | 允许上传和 hash 的静态 payload，返回独立数组。 |
| RuntimeFiles | 固定的四个运行状态文件名，不允许通过 FilePath/HashCommand 当作上传输入。 |
| OwnedFiles / OwnedFilePath | 仅构造受限的菜单任务拥有路径，包含预留 helper 和状态文件；不能访问 .owner 或任意相对/绝对路径。 |
| 原单插件构造 | 保持三个 payload、无菜单运行状态、原参数映射及原执行路径。 |

菜单准备清理在任何删除之前遍历普通和隐藏目录项，要求每个实际存在项都是本次允许的普通 payload 或 .owner，且不得是符号链接。出现未知普通文件、隐藏文件、子目录、预留而未上传的 launcher、任一运行状态文件、悬空链接，都会拒绝清理并保留 owner 和 payload。

预留运行状态不等于已经实现运行态清理。本阶段对任何运行状态文件均保守拒绝；以后需要由独立生命周期逻辑确认进程结束后处理。

只删除固定清单并使用 rmdir 移除空目录，没有递归清理或扫描删除其他任务。相邻任务目录保留；共享父目录不为空时不删除父目录。

## 7. 风险与边界

- 网络与 SFTP 准备使用 fake 验证；未实测 GitHub 响应、路由器 SFTP 或设备上的 BusyBox/ash。本地命令测试运行于 Windows Git Bash，不能替代真实 APK/OPKG 设备验收。
- SHA256 证明本地/上传字节一致；固定入口 SHA 不自动固定 menu.sh 后续自行下载的子脚本或附件，也不证明上游业务逻辑安全。
- 当前脚本校验复用严格 UTF-8、/bin/sh 头及大小/许可/hash；尚未进行设备侧 sh -n 或 PTY 执行验证。
- 本阶段的准备结果已经清理，不能持有它作为未来执行句柄。launcher 生成、运行态 PID/退出协议、已结束状态文件清理和 UI 接入留在后续阶段；发现运行状态文件时当前清理会明确失败并保留目录。
