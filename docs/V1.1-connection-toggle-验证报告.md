# SSH 连接 / 断开按钮切换

日期：2026-10-28（Asia/Taipei）。本轮完成首页按钮切换、主动断开、设备状态清理、离线测试和 Release x64 构建；没有连接或操作真实路由器。

## 最终行为

| 状态 | 按钮 | 行为 |
| --- | --- | --- |
| 未连接、无互斥任务 | 连接，可用 | 使用原有地址/用户名/密码检查、SSH 认证和环境检测流程 |
| 正在连接 | 连接中…，禁用 | 等待既有连接流程完成 |
| 已连接且空闲 | 断开，可用 | 主动关闭当前 SSH 会话，清理设备及维护状态 |
| 正在断开 | 断开中…，禁用 | 后台释放 SSH；界面继续响应，暂不接受新网络任务 |
| 安装准备/执行、软件检测、插件维护、连接任务占用 | 禁用 | 不允许通过旧的按钮快照绕过互斥 |
| 未确认安装/软件源恢复任务 | 禁用 | 保留原有任务及恢复所需认证，先处理旧任务 |

按钮文字由实际 `ssh.IsConnected` 和连接/断开进行状态计算，不再由安装或软件检测代码覆盖成“连接”或“连接并检测”。窗口原有尺寸、布局及按钮位置不变。

点击前复核界面和服务状态。若按钮仍显示“断开”时 SSH 恰好已掉线，按用户点击时的断开意图清除旧会话，不转而要求输入密码。若已有任务刚刚取得服务互斥，服务层拒绝断开，不清除当前设备和认证。

## 主动断开与清理

原服务的 Dispose 表示服务永久关闭，仅用于程序退出。本轮新增可重复使用的 `DisconnectAsync`：在共享锁下检查连接、软件任务、菜单生命周期和未确认安装 Gate；拒绝时返回 false，不取消运行任务。

允许断开时，原子取走当前/待连接客户端，清空服务引用、用于自动重连的 connectionFactory、持有密码的脱敏闭包引用及旧维护授权；在后台 Dispose 客户端，并复用连接操作 Gate 直到释放完成。服务本身不被标记 disposed，后续可重新连接。

界面随后清理：

- 标记旧 RouterEnvironment 已断开并将当前 router 置空；版本、SDK、架构、包管理器、QuickStart、设备详情及指纹不再显示为当前设备。
- 清空密码框并恢复密码遮罩；保留地址和用户名供下次连接。
- 清空软件环境状态、旧结果摘要及包差异显示，禁用软件检测、安装和插件维护入口。
- 保留本地已选安装包，其兼容性重新计算为 Unknown，连接新设备后再判断；不会删除文件。
- 保留历史诊断和安装日志。

主动断开后不再使用之前的认证自动重连，下一次连接需要重新输入密码。本次程序运行中的 Host Key 信任记录继续保留，仍会拒绝同地址的身份变化。

意外网络掉线继续沿用原有安装恢复策略：保留会话内认证及原设备身份供安装流程重连，不被误当作用户主动断开。现有 1 秒连接定时器刷新按钮；意外掉线时按钮变回“连接”，后台任务/未确认安装 Gate 仍有效。

若 SSH Dispose 抛出异常，服务引用及认证已清除，界面给出“关闭结果未能确认”警告；仅记录异常类型，不记录可能含敏感信息的异常原文，不把它显示为已确认的正常关闭。

## 风险及实机复核

- 主动断开会清除自动重连认证引用，需要重新输入密码；未确认安装任务会拒绝连接切换，防止丢失恢复上下文。
- 主动断开关闭的是本地 SSH，不承诺停止路由器上已存在的后台进程。维护窗口自身的安全关闭和未知状态复核规则保留。
- 实际 SSH 关闭耗时取决于运行环境，关闭期间按钮保持禁用、UI 不等待网络线程；异常会明确标注关闭未确认。
- 本轮未连接 N1。实机应复核连接成功→断开、空闲断开后的所有设备字段/维护入口、重新输入密码连接、首次安装及菜单准备/运行期间无法断开，以及意外掉线仍可按原安装流程恢复。
