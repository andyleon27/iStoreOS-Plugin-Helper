## 问题与修正边界

旧 CompatibilityService 对插件 / 设备 Architecture 做原字符串相等比较，导致 `aarch64` / `aarch64_a53` 与实际设备返回的 `aarch64_cortex-a53` 被误判为 Incompatible。设备版本 24.10.8、SDK 24.10、OPKG 等场景数据来自用户报告；修复不识别设备型号、IP 或测试机身份。

新增独立 `ArchitectureCompatibilityService`，集中做别名 canonicalization 与有方向的“插件 → 设备”判断，并返回日志说明。CompatibilityService 调用该层，SDK 比较仍为原来的严格 Ordinal 相等。

插件解析器仅扩充 Cortex-A53 / A72 token，保持最长 token 优先与原文件名解析流程；架构 token 采用 OrdinalIgnoreCase 识别，但取文件名中的原始子串用于模型和显示。不会把 Router.Architecture 改写成别名。

## Architecture rules

| 插件标记 | 允许的设备架构 |
| --- | --- |
| x86_64 | 只允许 x86_64 |
| aarch64 | aarch64，以及有非空后缀的 aarch64_ 家族设备架构 |
| aarch64_a53 / aarch64_cortex-a53 | canonical Cortex-A53；另允许 aarch64_generic |
| aarch64_a72 / aarch64_cortex-a72 | 只允许 canonical Cortex-A72，不允许 A53 或 generic |
| aarch64_generic | 只允许 aarch64_generic，不放行到 Cortex-A53 / A72 |

A53 → generic 为明确的 **Are-u-ok ARM64 compatibility rule**，说明会进入兼容性详情和高级日志，不作为通用 OpenWrt 软件包 ABI 规则。其他未定义的语义关系不做推断，仅保留精确匹配；文件名不认识的 token 仍保持 Unknown。

Canonicalization 将 a53 / a72 简写分别映射到 cortex-a53 / cortex-a72，使用 OrdinalIgnoreCase。原始插件 / 路由器值保留；成功映射示例为 `aarch64_a53 → aarch64_cortex-a53`，拒绝示例为 `✗ 插件架构 aarch64_a72 与目标 aarch64_cortex-a53 不兼容`。现有主界面简洁摘要保持，详细说明通过原有 tooltip / 高级信息 / 日志显示。

架构兼容并不替代 SDK 匹配：24.10 插件对 25.12 设备仍为 Incompatible。没有新增设备表、在线兼容表、内部 APK / IPK 架构解析、解包或安装流程。
