## 修复范围

### RemoteTempSession

用户报告 N1 / iStoreOS 24.10.8 / SDK 24.10 / aarch64_cortex-a53 / OPKG 在源切换与 update 成功后，因 `ash: stat: not found` 阻断于安装前。问题来自临时目录创建命令的 owner / mode 查询，并非远程文件大小校验。

`CreateCommand()` 现使用基础 shell / mkdir / chmod，完全移除 `stat` 依赖：

1. `umask 077`，任一步失败均通过 `&&` 停止后续操作。
2. 创建前检查 `/tmp/istore-plugin-helper` 非 symlink；不存在时以 mkdir 创建，不是目录则失败。
3. 创建后再次检查根非 symlink，强制 `chmod 700`；chmod 失败不创建 session。
4. session 使用随机 32 位十六进制 GUID，创建前同时检查不存在且不是 symlink，不复用已有文件 / 目录 / dangling symlink。
5. 独占 mkdir 后 `chmod 700` session，失败返回非零。
6. Cleanup 与文件白名单保持原实现，仍只允许 `/tmp/istore-plugin-helper/<32hex>`；拒绝 root、自定义目录、路径穿越、额外子路径或换行。

不安装 stat / coreutils / 任何路由器 package，不引入 Python、Perl、readlink、realpath 或 GNU find 依赖。没有为设备型号或 IP 写特例。此修复按用户指定的基础工具安全策略，以 symlink 防护、GUID、专属路径和 0700 权限替代旧 stat owner / mode 检查；未增加新的 owner 查询依赖。

### 安装前锁检查

全产品源码扫描发现 `InstallationReadiness.Busy` 还有一处 `stat -c %i`。现改为 `LC_ALL=C ls -di` 读取 inode，经 awk 提取并严格校验数字，再与 `/proc/locks` 匹配。inode 读取 / 解析失败、locks 不可读或 awk 检查异常返回非零，不误报 IDLE。APK / OPKG 进程、未结束安装 session、有限等待保持。

产品源码中 `stat `、`stat -c`、`command -v stat` 扫描均为零命中。`PluginInstallCommands.FileSize` 保持 `wc -c < package.run`，`SshPluginInstallSession.RemoteFileSize` 及其大小不一致阻断逻辑未修改。

### SoftwareEnvironmentService

仅删除换源失败条件中的 `!switched`，将该变量命名为 `acknowledged` 并记录日志。POST 回执未确认或应答中断后，仍以重新读取的实际状态判断：

- current identity 必须等于本次候选 identity。
- ReadOfficial 退出码必须为 0，完整 distfeeds 必须通过原 `MatchesFeeds` 校验。
- 解析实际配置并重新 Probe，必须 FULL。
- 实际 package update 必须成功才 Ready。

identity / feeds 不符仍拒绝，Probe 非 FULL 不执行该候选 update，update 失败沿用原候选尝试、非源错误停止与恢复规则。成功的独立环境修复继续保留健康源。

`InstallationWorkflowService` 原有实际状态验证、临时换源与安装后恢复原文策略保持原文件 SHA256；`QuickStartService.IsSuccessfulPost` 未修改，不猜测或扩大 POST JSON 协议。两条流程现均允许“回执未确认，但实际 identity / distfeeds 已验证成功”，且均不跳过实际 Probe / update。没有抽取大 helper 或重构安装核心。
