## 3. 项目结构变化

安装引擎只有一套：重新校验本地文件与设备 → 完整 V0.2 preflight → 空间检查 → 唯一 session → 上传 → SHA256 / Makeself → 最终确认 → 安装前快照 → 原始 `.run` → 安装后快照 / diff / 独立验证 → 清理。

主窗口只处理显示、确认、取消准备、互斥和日志保存。传输与安装服务通过 typed session 边界隔离，可用 fake 验证全部失败停点。主包差异只在轻量规则与候选识别中出现，没有为不同插件复制安装流程。

## 4. SSH.NET 上传实现

使用当前库的 `SftpClient.UploadFileAsync(Stream, path, false, IProgress<UploadFileProgressReport>, CancellationToken)`，复用连接工厂的 host / port / username / password，单独建立 SFTP client。上传不覆盖已有文件；前置本地文件句柄一直保留，禁止写入、替换和删除。

网络与哈希工作在 worker 执行，UI 保持响应。上传进度采用库报告的真实累计字节，按整数百分比节流，显示 percentage / uploaded / total；仅上传阶段显示百分比条。原安装阶段显示步骤与 stdout / stderr。

同步旧式 UploadFile callback 由库派发到 ThreadPool，不能从其中抛取消异常；当前实现使用可取消 task API 和 inline progress。API 核对来自[SSH.NET 2026.0.0 官方源码](https://github.com/sshnet/SSH.NET/blob/2026.0.0/src/Renci.SshNet/SftpClient.cs)及项目内 net462 XML 文档。

## 5. 是否使用 SFTP

**是。** SFTP 的 HostKeyReceived 必须同时满足与活动 SSH 的 SHA256 指纹一致，以及当前地址 / 端口已存在匹配信任记录。不会无条件接受，也不会为传输连接自行建立新 TOFU。密码仅在内存连接配置中使用，不写配置或日志。

真实设备是否提供可用 SFTP subsystem **尚未通过本程序实测**；本轮只完成实现、API / 依赖检查和失败分支测试。

## 6. 是否有 fallback

**没有 SCP fallback。** 当前 SSH.NET 有 ScpClient API，本版选择限定 SFTP；不是声称库没有 SCP 能力。SFTP capability / 认证 / 指纹 / 网络错误明确停止，不换用外部 scp.exe、Windows OpenSSH 或自制 SCP protocol。

## 7. SHA256 实现

Windows 使用 .NET `SHA256.Create()`，重新读取实际字节，没有调用 certutil 或 PowerShell。上传前后对同一锁定文件再次计算，远程必须大小一致；`sha256sum` 存在时摘要必须完全一致。摘要不符或不可解析都阻止 Makeself / installer。只有远程命令缺失时才附加 warning，使用大小与 Makeself `--check` fallback，不安装任何工具。

真实本地文件只读测量：83,179,363 bytes；SHA256 为 `956f12b53a970e7e36941cc000d5f441a3ef63ac5862f9b9a36a8def866bfdd1`，与用户历史值一致。该值仅在验收 fixture 对照中使用，业务代码没有硬编码。

## 8. Makeself 检测实现

上传后在本次目录执行 `sh package.run --info`、`sh package.run --check`，记录完整 stdout / stderr / exit。解析 Identification、Target directory、Uncompressed size、Compression 和 Makeself version；架构或 SDK 明确冲突停止。信息缺少可用架构时 warning，仍使用文件名与当前设备判断。

上传前 `/tmp` Available 必须大于 FileSize + 32 MiB；读取 --info 后必须大于解压大小 + 32 MiB，最终确认后再次检查。无法解析解压大小时 warning，保守使用 FileSize × 3 + 32 MiB。`df -Pk /tmp` 数值按 KiB 转为 bytes，支持 /tmp 继承父文件系统。

--check 必须 exit=0，且有 checksum OK / All good 证据；缺少 embedded SHA256 而 MD5 OK 是正常 fallback。行为核对来自[Makeself 官方 header](https://github.com/megastep/makeself/blob/master/makeself-header.sh)。业务没有硬编码真实 PassWall 的 Makeself 版本、目标或大小，也不做 Windows 本地解包。

## 9. Package Snapshot 实现

APK 使用 `LC_ALL=C apk info -v`；OPKG 使用 `LC_ALL=C opkg list-installed`。解析为 `Dictionary<string,string>`，空、重复或格式不可靠的 snapshot 报错，不能凭不完整数据显示成功。最终确认前读取预览判断已安装；确认后紧邻安装启动重新读取 BeforePackages，安装监测结束 / 异常后读取 AfterPackages。

完整快照保存到安装日志。APK 行为与独立查询核对来自[apk-info 官方文档](https://github.com/alpinelinux/apk-tools/blob/master/doc/apk-info.8.scd)和[官方实现](https://github.com/alpinelinux/apk-tools/blob/master/src/app_info.c)。

## 10. Package Diff 实现

按包名比较版本，生成 Added、Updated（包含任何版本变化）、Removed。结果区显示数量，日志显示包名及前后版本。不强依赖历史新增 5 / 升级 3；用户卸载主包后依赖可能仍保留新版。

## 11. Verification 实现

只有已确认的 PassWall → `luci-app-passwall`、OpenClash → `luci-app-openclash` 是强主包规则。其他插件检查 Added + Updated 中的 luci-app 候选，唯一候选优先；多个候选时用归一化名称选择唯一匹配。

候选必须存在于 AfterPackages，并通过独立 `apk info -e <package>` 或 OPKG status 的 installed 状态检查，才显示 SuccessVerified。已知主包缺失 / 独立查询失败为 FailedVerification；未知插件无法唯一确认时为 SuccessWithWarning。installer exit 非零为 FailedInstaller，即使主包已出现也不直接显示成功。

PassWall / OpenClash 的包版本与文件名版本都能解析为数字系列时，还核对系列一致性，防止已有旧包因更新内部失败却被误判成功；不要求一致的 APK revision 后缀。

安装前已有 OpenClash 时，安装后只读确认 `luci-app-openclash` 仍存在；丢失会明确失败并记录 warning。没有代理进程 / 通用 init running 判断，没有启停、卸载或 UCI 修改。已安装插件最终确认必须额外勾选继续安装 / 更新；不会静默重装。

## 12. Remote cleanup 安全机制

session 仅由程序生成的小写 32 位 GUID 创建，固定根为 `/tmp/istore-plugin-helper/`，固定远程文件名 `package.run`。创建要求 root 不是 symlink、属于当前 SSH UID、权限为 700，session 不能已经存在。所有路径做完整锚定验证，拒绝 root 本身、兄弟目录、子路径、换行和 traversal；shell 参数使用原有安全 quote。

仅在确认本程序创建了目录后，才允许清理它；创建失败不会删除一个未拥有的目录。清理前拒绝 root / session symlink，仅删除该完整合法 GUID 路径，检查整个目录与 package.run 不再存在，并记录清理前后 Available。Windows 原始文件从不删除、移动或重命名。

安装通过 nohup shell runner 执行一次作者原始 `sh package.run`，stdin 为 /dev/null，工作目录与 TMPDIR 均为本次 session；launch.once 防止同一 session 被重复启动。stdout / stderr 分别落到本次目录，退出码通过原子 rename 标记。每秒以有限时 SSH 命令增量读取最多 64 KiB / channel，UTF8 decoder 保留跨块字符，完整行组合后脱敏，结束时刷新残余行。完整安装日志只在用户主动保存时写入 Windows。

只有安装器未启动或明确结束时才 cleanup。监测无活动 15 分钟 / 总计 30 分钟超限、SSH 中断或启动响应丢失，都不会 kill 或 retry；会尝试独立验证，报告 InstallerStateUnknown，并保留可能仍在使用的目录。正常成功 / 失败 / 取消准备路径都做 best effort cleanup；清理失败不抹去已验证的安装成功，而是附加 warning。异常退出遗留目录不做自动垃圾回收。
