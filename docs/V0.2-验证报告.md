## 11. 软件源切换情况

实机日志最终明确记录 **`source switch=False`、`POST attempted=False`**，与用户“未切换”的确认一致。当前源保持 CERNET，本轮没有进入候选切换或恢复流程，没有创建恢复备份，也没有人为制造故障。自动切换与 recovery 目前只在 mock 中验证。

健康路径不调用候选列表或 POST，不创建恢复备份。修复路径只读探测动态候选，FULL 才可参与排序；首次 POST 前列出候选，用户点击“自动修复”后才备份与切换。切换后复核当前 identity 与 distfeeds 的全部完整索引路径，并重新探测实际配置和执行 update。

成功保留新健康源。未成功 / 取消 / 异常时，优先通过原内置 identity 恢复，再以备份原文进行最后 recovery；核对完整文本，恢复失败明确标记 RecoveryFailed，并保留备份位置。只写固定官方 distfeeds 路径；备份目录由 mktemp 创建，不覆盖已有用户文件。

候选数据与模板行为依据[QuickStart 官方 models](https://github.com/istoreos/quickstart/blob/main/backend/models/guide_soft_source_list_response.go)和[官方源读写实现](https://github.com/istoreos/quickstart/blob/main/backend/service/guide_soft_source_store.go)核对，实际候选来自目标路由器，不硬编码历史 8 个镜像。

## 12. 已知问题与限制

- 实机健康路径已通过；初次 telephony TLS 错误在 update 后只读复核时恢复正常，未触发换源。真实切换与 recovery 路径仍只有 mock 测试证据。
- iStoreOS 22 / 24 的 OPKG 分支保留并有解析 / 命令测试，没有声称真实设备验收；Win7 仍未实测。
- URL probe 与 QuickStart POST 需要路由器已有 curl；程序不会安装 curl 或其他 agent。Range 被拒绝或忽略导致超限、TLS 校验失败等都会报告探测失败，不绕过安全校验。
- QuickStart 不可用时可检查当前源并 update；缺少动态候选 / ROM 模板时不猜测源、不绕过认证，也不直接写另一套软件源模板。
- 恢复依赖 SSH 连通；如果设备断电或连接断开，无法保证当场恢复，程序会保留备份并明确报告 RecoveryFailed。
- 关闭检测窗口需要等待当前有时限的命令结束与必要恢复，避免中断源修复。
- 恢复备份保留用于人工检查，没有加入自动清理功能。
