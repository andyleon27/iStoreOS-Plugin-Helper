日期：2026-10-29（Asia/Taipei）。本地开发功能，产品元数据仍为 V1.0.2，未发布。未连接路由器，未执行真实包安装。

## 实现逻辑

首页文件选择和单文件拖入同时接受 `.run`、`.ipk`、`.apk`，扩展名不区分大小写。拒绝其他扩展名和多文件拖入；选择失败清除旧包及兼容状态。状态区显示包内名称、完整版本、架构和格式；原生包不显示虚构 SDK。

连接时通过现有只读设备检测识别包管理器，增加可执行文件及 APK / OPKG 已安装数据库检查，保留软件源配置与单一可执行文件回退。安装前及重连时仍重新核对设备身份、包管理器、架构和 SDK。

| 文件 | 元数据与兼容条件 | 实际安装命令 |
| --- | --- | --- |
| `.run` | 原有文件名 SDK / 架构规则，上传后 Makeself `--info` / `--check` | 原始 `sh package.run` |
| `.ipk` | 读取 control 中 Package、Version、Architecture、Installed-Size；必须 OPKG；架构严格相同或 `all` | `opkg install '<本轮目录>/package.ipk'` |
| `.apk` | apk-tools v2 `.PKGINFO` 或 v3 ADB pkginfo；必须 APK；架构严格相同或 `noarch` | `apk add '<本轮目录>/package.apk'` |

原生包不套用 `.run` 专用 ARM64 别名 / generic 映射，不按文件名推断元数据。不能确认格式、必需字段或兼容性时禁止安装。支持 gzip/tar 与 ar IPK；支持 APK v2 分离 gzip 成员，以及 APK v3 未压缩、deflate、zstd。Android APK 拒绝。

读取元数据不提取任何归档路径，不运行包脚本。元数据有字节和条目上限，校验 tar 头并拒绝重复关键字段、符号链接元数据、扩展路径覆盖、越界 ADB 指针、不合法 UTF-8 和危险包名。包名最长 255 字符；IPK 外层扫描最多 512 MiB；gzip 控制元数据最多 1 MiB；ADB 元数据最多 8 MiB；zstd 窗口最多 8 MiB。超过边界明确拒绝，不降级成文件名猜测。

## 复用安装链与安全边界

1. 连接 / 身份复核，读取文件元数据；用禁止写入、替换和删除的本地文件句柄重新读取元数据及 SHA256，将元数据与实际上传字节绑定。
2. 复用真实软件源检测、镜像选择、package update、网络 / DNS / 时间、包管理器忙状态检查；`.run` 原有源选择、有限恢复流程保留。
3. 复用 `/tmp` 空间与安全余量；原生包额外按声明的安装字节加 32 MiB 检查持久存储，并在派发前再次复核。未声明大小按文件大小 3 倍估计。依赖的额外空间由包管理器继续处理。
4. 复用私有随机 session 目录、受信任 Host Key 和 SFTP；远端文件名固定为 package.run / package.ipk / package.apk，用户本地文件名不会进入远端命令。
5. 复用文件大小、本地 SHA256、远端 SHA256。原生包远端没有 sha256sum 时拒绝；`.run` 原有 Makeself 降级规则保留。IPK / APK 不执行 Makeself。
6. 复用安装前预览、正式 BeforePackages、启动前上传校验、launch.once、防重复派发、HUP 忽略、独立 stdout / stderr、原子 exit.code 和 SFTP 输出排空。
7. 设备包管理器执行本地文件安装，保留其依赖、架构、ABI 和签名检查，不添加 `--force-*`、`--allow-untrusted` 或自动卸载 / 回滚。
8. 复用 AfterPackages、Package Diff 和独立存在性查询。原生包要求包内名称存在、完整版本（含 revision）精确相等且独立查询成功；旧版本存在不能冒充本次成功，非 LuCI 包同样可验证。
9. 安装前取消走清理；派发后不取消 / 自动重派。断线沿用同设备有限重连并监测原 runner。未知状态保留目录和安装互斥；确认结束才按原顺序处理源状态与临时目录。

## 风险与实机验收

尚未进行真实设备 IPK / APK 安装；离线 fake、真实包格式解析和旧 .run 回归不能替代设备安装验收。建议使用可恢复的测试环境，先选择可信且非关键的小包。

- OPKG / APK 设备分别验证选择、拖入、名称版本架构显示；跨包管理器和错误架构应禁用安装。
- 各安装一个可信匹配包，检查 package update、SFTP、两端 SHA256、命令、exit.code、Before / After / Diff、包名 / 完整版本独立验证与清理。
- 验证安装前取消、SSH 断线、未知 runner 状态保留、重连监测；不要为测试强制中断正在修改系统的包管理器。
- 原生包元数据通常不包含可直接对比的固件 SDK；工具不将“包管理器 / 架构匹配”当成依赖、kernel ABI 或签名保证。已有源、系统版本和包依赖仍可能使包管理器拒绝。
- 本地 APK 的未签名 / 未受信任签名包可能被 `apk add` 拒绝。本轮保留签名校验，不自动绕过；需可信签名或设备已信任的包。
- 安装大小是包声明值 / 保守估计，不含所有依赖、安装脚本额外写入和文件系统开销；安全余量可能拒绝剩余空间很小的设备。
- 非标准压缩、扩展路径元数据或超出解析窗口 / 大小上限的包会拒绝；不会静默放行。SHA256 证明传输字节一致，不证明包来源可信。
- 安装脚本由设备包管理器以现有权限运行，可更改系统；未知状态不保证远程进程已停止，必须先检查原任务，避免重复安装。
