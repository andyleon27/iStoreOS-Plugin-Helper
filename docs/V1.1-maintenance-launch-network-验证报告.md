# 插件维护最终入口与启动编排

日期：2026-10-29（Asia/Taipei）。本轮完成首页入口、后台网络检测、点击复核、菜单临时代理及退出清理，并完成 Release x64 构建和完整离线回归。

**最终状态逻辑**

| 状态 | 入口表现 | 后续行为 |
|---|---|---|
| SSH 未连接、身份未确认或窗口关闭 | 灰色、不可用 | 不发网络检测，不创建 SSH #2 |
| 连接、网络检测、安装、软件检测、维护运行或未处理安装任务占用 | 灰色、不可用 | 服务层复核互斥；网络检测期间安装、软件检测和断开按钮同步禁用 |
| N1 直连 Raw 成功 | 启用“插件维护 ›” | 点击后复核，保持直连时不创建 SSH #2 |
| N1 直连 Raw 失败，Windows localhost HTTP 代理访问 Raw 成功 | 启用“插件维护 · 电脑代理 ›” | 点击后复核，再创建专用 SSH #2 |
| 两条 Raw 路径均不可用或检测无法确认 | 灰色、不可用 | 后台稍后重试 |
| Raw 可用，但 GitHub API 403、超时或异常 | 保持对应路径可用 | API 状态仅记诊断，不参与 Raw Gate |

网络快照绑定当前 SSH 客户端。可用状态 30 秒后重新检测，不可用状态 10 秒后重试；忙状态下不启动新检测。断开、重新连接、安装重连和服务关闭会使旧快照失效。检测异步完成后也复核客户端身份，不把旧设备的结果写入新连接。

后台检测只执行固定的 N1 直连探测和 Windows 本地 HTTP 代理探测，不创建隧道、不下载或运行菜单。代理候选来自系统 localhost 代理地址和常见监听端口；候选必须实际通过 HTTPS Raw 请求才可用，不把 SOCKS 或仅监听的端口当成 HTTP 代理。Windows 探测显式使用回环代理，不传默认凭据，不修改系统代理设置。

**点击与维护生命周期**

点击先复核 SSH、身份和忙状态，随后在同一个维护 lease 内重新探测当前 Raw 路径。缓存只决定入口显示，不能代替启动复核：原来直连、现在需代理时会切换到代理；原来代理、现在直连恢复时不会创建 SSH #2。两条路径此时都失败则不下载菜单、不上传文件、不启动 PTY。

直连流程：复核 Raw → Windows 沿用原有下载策略取得 upstream main 的 menu.sh/许可证 → 内容检查、本地 SHA256、独占远端目录、受信任 SFTP、远端 SHA256 → 首页 SSH #1 的独立 PTY → 菜单及其子脚本使用软路由网络 → 原有退出协议和清理。

电脑代理流程：复核 Windows Raw 代理 → 通过正式认证/Host Key 上下文创建 SSH #2 → 固定 `127.0.0.1:17890` 回环转发 → 验证隧道 Raw，API 仅诊断 → Windows 菜单/许可证下载请求也显式绑定同一已验证的 localhost 代理 → 保留全部 SHA256/SFTP/任务目录边界 → 通过 #1 的 PTY 运行菜单。

代理变量写在校验并上传的 launcher 中，仅作为 `sh "$menu"` 这一个命令的环境。代理路径下，http_proxy、https_proxy、HTTP_PROXY、HTTPS_PROXY 指向 `http://127.0.0.1:17890`，清空 NO_PROXY/no_proxy 与 ALL_PROXY/all_proxy 干扰；直连路径下清空显式代理，并设置 NO_PROXY/no_proxy 为 `*`。子 shell 和下载工具继承环境，父会话不被 export 或永久配置修改。PTY 的短启动命令仍为原有 exec launcher，未增大，也未修改上游 menu.sh 的字节或版本解析逻辑。

菜单正常结束、异常结束、窗口返回/标题关闭、启动取消或代理掉线，均收束到同一个清理链。先结束/排空菜单 PTY 并沿用原有运行状态协议，再断开并释放专用 SSH #2，由 #1 检查远端监听消失和旧代理地址 curl 连接失败。窗口等待该链完成后再返回首页。

代理连接异常会取消本次菜单；代理 controller 关闭回调不会提前清除仍在运行的维护 lease。直到菜单和代理清理结束才恢复忙状态。首页 SSH #1 不会因维护关闭而 Dispose 或自动重连。若 #1 同时断线，远端端口释放保留 Unknown，并显示清理警告。

**风险与 N1 验收**

- 本轮完成离线整链，尚未重新实测新版正式入口；此前独立双 SSH POC 的成功记录不能替代这次 UI/启动编排的实机验收。
- 仅自动识别系统配置和常见 localhost 端口；未登记的自定义端口可能无法发现。N1 需要已有 curl 和可读的 TCP 状态，不会自动安装或修改服务端配置。
- Raw 检测证明当前网络路径，不保证后续 SFTP、磁盘、下载内容和上游脚本一定成功。直连路径的菜单准备仍依赖 Windows 原有下载策略；电脑代理路径对下载请求显式绑定所选端口。
- 整个路由和代理状态可能在复核后变化。#1 失联时无法证明远端监听释放，结果保持 Unknown；未知菜单状态继续保留任务目录。
- 上游子脚本可自行重写环境或派生后台任务。关闭 PTY 和隧道不等于所有远端操作都已停止；回环端口也不隔离 N1 上的其他本地进程。本轮没有修改上游脚本或永久代理配置。

N1 验收清单：

1. 未连接时确认入口灰色；连接后检查检测中状态和首页互斥按钮。
2. N1 Raw 直连可用时，入口为普通“插件维护”；打开菜单并输入 `0` 退出，确认没有 SSH #2 或 17890 监听。
3. N1 Raw 直连不可用、电脑 HTTP 代理可用时，入口标记电脑代理；打开菜单，确认 Raw 验证通过、API 失败仅诊断，菜单输入正常。
4. 正常退出、返回首页、标题关闭后，检查代理清理结果为 Released、17890 无监听，首页 #1 仍连接。不要通过安装操作测试退出。
5. 两条路径不可用时确认灰色；恢复路径后等待后台重试。改变路径后立即点击，验证走新的复核结果。
6. 分别模拟电脑代理停止和 SSH 断线，检查菜单取消、清理等待与 Unknown 警告，不把未确认状态记为成功。
