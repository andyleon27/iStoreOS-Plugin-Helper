## 2. 启动和文件协议

调用方为每次运行分配非空 runId，使用 `RemoteMaintenanceWorkspace.CreateMenu(operationId, true)` 显式包含 helper-launcher.sh。普通单插件目录、未声明 launcher 的菜单目录都不能创建运行协议。

启动命令只有一行，UTF-8 长度上限 256 字节：

~~~sh
exec sh '/tmp/istoreos-plugin-helper/maintenance-<operationId>/helper-launcher.sh'
~~~

`StartPayload` 只在该命令后追加一个 LF，不把脚本主体放入 PTY，不附带下载命令。`LauncherBytes` 返回独立、无 BOM、LF 换行的 UTF-8 脚本；launcher 在前台调用 `sh "$menu"`，保留菜单输入和输出。

任务目录包含阶段 2 的 menu.sh、LICENSE、NOTICE.txt，以及显式新增的 helper-launcher.sh、原有 .owner 和四个运行文件：

| 文件 | 写入和用途 |
|---|---|
| menu.pid | 用 noclobber 原子认领 launcher PID；重复或并发启动不能覆盖。 |
| menu.start | 完整版本/任务 ID/运行 ID/START/PID/进程启动 ticks/Unix 启动时间。 |
| menu.exit.tmp | 退出记录暂存；存在时状态为未知并禁止清理。 |
| menu.exit | 前台菜单实际返回后写入暂存文件，再原子 rename 成正式退出记录。 |

PID 指向持有菜单的 launcher。进程启动 ticks 来自 `/proc/<pid>/stat` 第 22 字段，用来区分 PID 复用；Unix 秒来自设备 `date +%s`，用于显示时间。解析进程 comm 时允许空格和括号，不依赖 awk。

启动前验证任务归属、目录与文件的非符号链接属性、载荷白名单、运行文件不存在及 `sh -n menu.sh`。launcher 不自行清理目录。收到 HUP/INT/TERM 或被 KILL 时，不能证明前台菜单已实际返回，因此不制造正常或异常退出证据，保留未知状态及任务文件。

运行标记使用不可见 OSC：`ESC ]777;记录 BEL`；解析器也支持 `ESC \\` 终止。记录正文：

~~~text
ISTORE_MENU_V1|<taskId:N>|<runId:N>|START|<pid>|<startTicks>|<unixSeconds>
ISTORE_MENU_V1|<taskId:N>|<runId:N>|EXIT|<pid>|<startTicks>|<unixSeconds>|<exitCode>
~~~

解析器在 TerminalScreen 过滤 OSC 前被动观察原始输出，不改写终端文本。单帧最多缓存 512 个字符，能跨任意块边界恢复标记；普通菜单提示、SUCCESS、ERROR 字样均不决定运行结果。

## 3. 状态判定和清理时机

| 证据 | 状态与行为 |
|---|---|
| 已开始等待 START | Starting。 |
| 合法 START，尚无 EXIT | Running。 |
| 合法匹配 EXIT，通道尚未关闭 | AwaitingClose；退出标记不会提前触发清理。 |
| 输出读取结束，START/EXIT 身份匹配，退出码为 0 | ExitedNormally；仍需远端复核才允许清理。 |
| 同上，退出码为 1–255 | ExitedWithError；完整远端复核后允许清理。 |
| 仅 EOF、缺退出、通道错误、矛盾或无效的本任务记录 | Unknown；隐藏无依据的退出码并保留任务文件。 |

相同 START/EXIT 重复记录幂等，计入 DuplicateMarkers；不同 taskId/runId 的标记被忽略。相同任务出现不同 PID/时间/退出码、非法数字或完整记录矛盾时，持续保持未知，后续远端回复不能覆盖冲突。

`ReadStateCommand` 返回且只返回一条绑定 taskId/runId 的 STATE：NOT_STARTED、RUNNING、EXITED 或 UNKNOWN。读取限制 512 字节，验证 .owner、普通文件、非符号链接、严格字段及数字范围，并检查 `/proc`：

- 同一 PID 与 startTicks 仍存活，即使已有退出文件，也拒绝完成清理。
- PID 已被复用时，不把新进程误认为旧 launcher。
- `/proc` 无法读取、退出缺失、临时文件、错误任务/运行 ID、身份矛盾均归未知。
- 流尾部标记丢失或传输中断，可由同一任务的完整持久 EXITED 证据恢复；完整标记冲突不能恢复。

客户端只有在 `Complete` 之后、最终状态已知、远端 EXITED 证据通过时才给出 CanCleanup。`Complete` 必须在输出读取结束后调用，主动停止/取消应传入对应错误；不能把发送退出命令或收到 EXIT 当作输出排空。

`CleanupFinishedCommand` 在远端重新检查状态和全部目录项，只删除本任务固定白名单文件；未知项、隐藏项、符号链接、仍运行或不完整状态均保留。无递归删除、不终止进程、不删除相邻任务。删除成功后返回绑定任务和运行的 CLEANED，客户端通过 `ConfirmCleanup` 确认。清理完成后拒绝旧状态或延迟输出重新激活任务。

## 5. 后续接线和风险

1. 阶段 2 的准备接口仍是清理后返回的预览。真实运行接线必须建立新任务，在同一活跃目录上传并校验 menu.sh、LICENSE、NOTICE.txt 和本次 runId 对应 launcher，不能复用已经清理的准备结果路径。本轮不改变准备接口生命周期。
2. 尚未验证路由器 BusyBox ash、真实 ShellStream/PTY、Ctrl+C 的进程组行为或网络断连。后续接线需在原始输出回调中先 Feed，再送 TerminalScreen；读取结束后 Complete，再复核状态和清理，不能同步阻塞 UI。
3. Unknown 会有意保留运行文件，没有自动杀进程或强制清理。需要后续提供明确状态展示及人工恢复入口。
4. 退出码 0 只说明 menu.sh 进程返回成功，不证明其中每个插件动作成功；启动显示时间依赖设备时钟，进程身份比较使用独立的 startTicks。
5. 状态协议用于同一已认证连接上的归属和一致性验证，不能防御拥有同等远端权限的进程主动篡改文件或伪造记录。

原未提交工作区及前两阶段源码均已保留；本轮无 stash/reset/clean、提交、推送或真实设备操作。
